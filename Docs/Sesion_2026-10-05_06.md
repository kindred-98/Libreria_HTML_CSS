## 2. Fase 0 — Cimientos de ingeniería

**Por qué primera:** todo lo demás es una apuesta sin red. Con linter, tipos y
tests, las fases siguientes no pueden romper nada en silencio.

### Qué se añadió

| Herramienta | Alcance | Comando |
| --- | --- | --- |
| Tests unitarios (`node:test`) | `Web/scripts/__tests__/` — **48 tests** | `npm test` |
| Tests e2e (Playwright) | `Web/scripts/e2e/` — **15 tests** | `npm run test:e2e` |
| ESLint (flat config) | solo `Web/scripts/` | `npm run lint` |
| Prettier | solo `Web/scripts/**/*.mjs` | `npm run format:check` |
| TypeScript (`checkJs`) | scripts de Node, con **presupuesto** | `npm run typecheck` |

**Cero dependencias nuevas de producción.** `node:test` y `playwright` ya
estaban o son nativos. Lo único añadido: `eslint`, `prettier`, `typescript` y
`@types/node`, todos de desarrollo.

### Tres decisiones que conviene no revertir

1. **No se lintean los 1018 demos.** Son componentes para copiar y pegar tal
   cual (regla 6 de `CONTRIBUTING`). ESLint daría miles de avisos inservibles;
   SonarQube ya los analiza. Está escrito en `eslint.config.mjs` para que no
   parezca un olvido.
2. **No se formatea con Prettier fuera de `Web/scripts/`.** Formatear los demos
   reescribiría cientos de miles de líneas sin cambiar comportamiento y
   rompería las métricas de SonarQube. Está en `.prettierignore`.
3. **El typecheck es un presupuesto, no un `0`.** Quedan **18** errores de
   tipado en código heredado. La puerta exige que `lib/` y `__tests__/` estén
   **siempre a cero** y que el total **no crezca**. La deuda solo puede bajar.

### Errores propios que encontraron las herramientas

- **`EXCLUIR` del autofix no funcionaba en Windows.** Comparaba
  `"Web/scripts/lib/"` contra una ruta con **backslashes**, así que `includes()`
  nunca casaba y `lib/` **sí se autoeditaba**. Llevaba tiempo roto.
- **`S7765` prometía más de lo que hacía.** La documentación decía que también
  convertía `>= 0`, pero la regex solo aceptaba `-1`. Al arreglarlo, el primer
  intento convirtió `!= 0` y `> -0`, que **no** son `includes()`: casi se
  introduce un bug peor. Ahora hay tests que protegen los tres casos.

## 3. Fase 1 — SonarQube

### El punto de partida era mejor de lo que parecía

Medido hoy sobre la rama principal: **97 incidencias abiertas**, de las que:

| | |
| --- | --- |
| BUG | **3** (los tres son `S3403`, ver §6) |
| VULNERABILITY | **0** |
| CODE_SMELL | 94 |
| Severidades | 0 CRITICAL · 43 MAJOR · 50 MINOR · 4 INFO |

**29 incidencias arregladas** en dos tandas: 21 en demos (mecánicas) y 8 en el
código de `Web/scripts`.

### Lo que sí se arregló (y era real)

- **Path traversal cerrado.** `Web/scripts/test.mjs` concatenaba `process.argv`
  a una ruta sin validarla: `node test.mjs ../../` leía ficheros fuera del
  repositorio. Ahora hay lista blanca (`__tests__`, `e2e`) y comprobación
  explícita.
- **Complejidad cognitiva (S3776).** `getLocalReferences` en
  `generate-catalog.mjs` tenía 19 puntos de complejidad contra 15 permitidos.
  Se extrajeron las tres barreras de seguridad de rutas a una función con
  nombre, `leerSiEsFicheroLegible`. **Verificado: el `catalog.json` generado
  sale byte-idéntico** (`sha256` igual), así que el refactor no movió ni una
  referencia.
- **`void` que se comía errores.** `void initializeApp()` silenciaba el fallo
  de arranque: si el catálogo no cargaba, la página se quedaba a medio pintar
  sin explicación. Ahora lleva `.catch()` con log.
- **Trampas de reflow documentadas.** `void element.offsetWidth` era
  intencional (fuerza al navegador a releer el layout). Pasó a un helper
  `forzarReflujo()` que hace lo mismo pero explica la intención.

## 4. Fase 2 — Accesibilidad: 85 → 100

Es la nota que más fácil subió y la que más cambios reales implicó.

| Regla | Antes | Ahora |
| --- | --- | --- |
| `aria-allowed-role` | **33** | **0** |
| `heading-order` (catálogo) | **8** | **0** |
| `landmark-unique` | **4** | **0** |
| Objetivos táctiles (<24 px) | **38** | **0** |
| Lighthouse escritorio | 95-100 | **100 en las 5 páginas** |

### El cambio de fondo: tarjeta enlazable

La tarjeta del catálogo era `<article role="link" tabindex="0">`. Eso es:

- **un rol que axe rechaza** (`aria-allowed-role`: un `article` no admite rol de enlace);
- **dos puntos de tabulación por tarjeta**, porque la tarjeta era tabbable *y*
  dentro tenía su propio `<a>`.

Ahora el `<article>` es un `article` normal y el enlace "Ver componente" cubre
toda la tarjeta con un pseudo-elemento (`.card-link::after`). Se eliminan los
manejadores de Enter/Espacio a mano: los resuelve el navegador.

El enlace lleva `aria-label` con el nombre del componente **conteniendo** el
texto visible ("Ver componente: Bengala"), que es lo que pide la regla
*label in name*.

### Lo que costó un intento

Las tarjetas repetidas del carrusel de la portada se marcaron `aria-hidden`
primero, y axe respondió `aria-hidden-focus`: un contenedor oculto no puede
contener nada enfocable. La solución correcta era **`inert`**, que hace las dos
cosas a la vez (no anunciado + fuera del recorrido de teclado) y sigue
permitiendo ver y pulsar con el ratón.

### Objetivos táctiles

Medido a 360 px con `pointer: coarse` (hay dedo): de 38 y 19 controles por
debajo de 24 px a **0**. Se usa `pointer: coarse` a propósito: en escritorio,
con ratón, ampliar controles solo gasta sitio.

## 5. Fases 4a y 4b — Producto y mercado

### 4a — Legal (la nota más baja del plan: 68)

`PRIVACY.md` llevaba días escrito en la raíz, pero **nadie llegaba desde la
web**. Para un sitio con Google Analytics, eso es un problema, no un detalle.

- `Web/privacidad.html` y `Web/legal.html`, bilingües, con índice.
- Enlazadas desde el pie de las tres páginas + `sitemap.xml`.
- **Declaración de accesibilidad** con el nivel medido de verdad, no un
  "somos accesibles" inventado.

### 4b — Descubrimiento, instalación y medición

- **JSON-LD** (`WebSite` + `SearchAction` + `SoftwareApplication`,
  `CollectionPage`), validado como JSON.
- **`hreflang`** (es/en/x-default) en las cinco páginas.
- **Manifest e iconos reales** generados del favicon con el Chromium que ya era
  dependencia (sin `sharp`). El `apple-touch-icon` era un SVG y **Safari lo
  ignoraba**.
- **Seis eventos de GA4** formando el embudo completo: `busqueda_iniciada`
  (solo la longitud, nunca el texto), `filtro_categoria`, `filtro_autor`,
  `ver_componente`, `descarga_zip` y `cambio_idioma`. Antes había dos y
  ninguno era una acción de valor.

### Un problema que salió al verificar Search Console

**Google solo busca `robots.txt` en la raíz del dominio**, y el fichero vivía
en `/Web/`. En la raíz daba 404, así que el buscador no veía ni el robots.txt
ni la línea `Sitemap:` de dentro. Se añadieron dos redirecciones 302 en
`vercel.json`. Detalles en [`Search_Console.md`](./Search_Console.md).

## 6. Lo que se decidió NO hacer, y por qué

Todo esto está en [`Sonar_decisiones.md`](./Sonar_decisiones.md); aquí el
resumen.

| Decisión | Motivo |
| --- | --- |
| **Los 3 BUG (`S3403`) quedan como están** | Falso positivo: la variable nace como `""` pero se reasigna dentro de un callback, y el analizador no lo ve. La "corrección" probada (`String()`) deja el mismo valor. Los tres están en demos de autores. |
| **`S1940` (invertir operandos)** | Rompió 5 demos: `a > b` y `b < a` no son equivalentes con coerción de strings. |
| **`S7747` en `detectar-duplicados.mjs`** | El spread `[...set]` **no** es redundante: dentro del bucle se borra del `Set` que se recorre. |
| **`S107` (8 parámetros) en `fourier-epicycles`** | Reducirlos puede romper el dibujo de las estelas. |
| **El `<header>` de 23 líneas repetido** | Sitio estático **sin build a propósito**: funciona sin JavaScript desde el primer byte. Componerlo exigiría un paso de build que el proyecto no quiere. |
| **Partir el diccionario i18n en dos ficheros** | Se probó y **rompió el sitio entero**: `app.js` es script clásico (`<script defer>` sin `type="module"`), que no admite `import`. Los 15 tests e2e lo detectaron y se revirtió. |

## 8. Un aviso sobre las measurements

Todas las cifras de este documento se midieron con comandos del repositorio,
no son estimaciones:

```bash
npm test                      # 48/48
npm run test:e2e              # 15/15
npm run lint                  # 0 errores
npm run typecheck             # 18 de 38
npm run validar               # 1018/1018
npm run validar:lighthouse    # 5 páginas x 4 categorías
npm run sonar:exportar        # 97 abiertas
```

Lo que **no** está medido y no debe darse por hecho:

- **Lighthouse móvil** es una simulación con CPU ×4 y red estrangulada. La cifra
  real en un móvil de gama media es mejor, pero no se ha medido en un
  dispositivo físico.
- **La nota de producto/mercado (96)** es una estimación sobre las 20 casillas
  de §7 del plan. Dos de ellas siguen sin hacer: cómo usar un componente y el
  anuncio de la release.
