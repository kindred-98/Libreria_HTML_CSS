Halyard API · Reference

Everything the API does, in the order you will need it.

Halyard moves bookings between harbours, ferries and repair yards. This reference covers the four endpoints that most integrations start with, plus the error codes, webhook payloads and rate limits you will meet in the first week of production traffic.

01 · Guide

Quickstart

Every integration begins with a single key and a single request. Create a key in the console, then ask the availability endpoint which berths are free between two timestamps; the response is a plain list of berth identifiers with their harbour code.

GET /v4/berths/availability?from=2026-04-12T06:00Z
Authorization: Bearer hk_live_2f1c…
X-Halyard-Client: ferry-ops

Keys are scoped to one harbour group. A key that can read availability cannot write bookings, and the console will refuse to issue a write key until a contact address has been confirmed.

02 · Guide

Authentication

Send the key as a bearer token on every request. Tokens are shown once at creation, stored only as a hash, and can be rotated without downtime: the previous token keeps working for twelve hours after the new one is issued.

curl https://api.halyard.example/v4/berths \
  -H "Authorization: Bearer hk_live_2f1c…"

Server-side calls only. A key that appears in a browser, a mobile bundle or a public repository is revoked automatically within a minute of the scanner finding it, and the console records who shipped it.

03 · Guide

Rate limits

Reads are limited to 600 requests per minute per key and writes to 120. Every response carries the four standard headers, and the limit resets on a sliding window rather than a fixed boundary, so a burst at the top of the minute does not lock you out of the next one.

X-RateLimit-Limit: 600
X-RateLimit-Remaining: 587
X-RateLimit-Reset: 1775059260
Retry-After: 12

On 429, back off for the number of seconds in Retry-After. Retrying immediately is counted against the same window and will simply fail again.

04 · Guide

Webhooks

Four events are published: berth.booked, berth.released, vessel.arrived and payment.failed. Each payload is signed with HMAC-SHA256 over the raw body using the endpoint secret, and the signature is sent in the X-Halyard-Signature header.

Delivery is attempted five times over thirty minutes with exponential backoff. An endpoint that returns 200 for one hour is marked healthy in the console; one that fails every attempt for a day is paused and the owner is emailed.

05 · Reference

Error codes

Errors return a machine-readable code, a human message and a request_id that appears in the logs for ninety days. Quote the request id when writing to support and the responder can see the exact request without asking for a trace.

  • 4001Malformed timestampCheck the ISO 8601 format
  • 4013Key lacks harbour scopeIssue a key for the right group
  • 4091Berth already bookedRetry with another berth
  • 4290Rate limit exceededBack off using Retry-After

06 · Reference

Client libraries

Official clients exist for Python, Ruby, Go and TypeScript. All four handle retries, signature verification and the sliding rate limit window, and all four ship the same fixtures so that a payload decoded in one language is byte-identical in another.

pip install halyard
halyard keys list --harbour ridgeway

Community clients are listed in the sidebar of the console with their last release date. Anything older than two major versions of the API is flagged rather than removed.
